25/10/2026, America/Bogota. Se aplica el contrato de [plan-monitoreo-local-2026-10-25.md](plan-monitoreo-local-2026-10-25.md): presupuesto adicional US$0, Grafana OSS y Prometheus ejecutados en este Windows; único origen remoto, HTTPS de Cloud Run. No se despliega ni modifica infraestructura en este incremento.

## Alcance y decisiones antes de implementar

1. Crear scripts PowerShell 7 de instalación/configuración, arranque, parada y comprobación en `scripts/observability/local`. Toda herramienta descargada, datos TSDB/SQLite, logs, PID/manifiestos y secretos quedan fuera de Git bajo `%USERPROFILE%\.grownupsvet\monitoring`. Rechazar rutas con reparse points y limitar las operaciones al árbol privado. ACL de ese árbol: usuario actual y SYSTEM, sin herencia. No tocar el respaldo Render ni su automatización.
2. Reutilizar Prometheus/promtool 3.15.1 ya verificados en `output/backend-cierre-2026-10-25/observability-tools`, volviendo a calcular hashes. Descargar exclusivamente el paquete portátil oficial **Grafana OSS 13.2.4 Windows AMD64**, sin instalador global ni Enterprise. Verificar SHA-256 publicado antes de extraer. Conservar manifiesto de procedencia/hashes de binarios y configuraciones. No añadir servicios Windows, tareas de arranque o Docker.
3. Generar una única credencial máquina de 32 bytes CSPRNG, Base64URL sin padding (43 caracteres). Guardarla como archivo privado UTF-8 sin BOM y sin pasarla por argumentos, consola, logs o Git. Calcular SHA-256 de esos 43 caracteres UTF-8 y escribir un archivo separado `backend-monitoring.env` con `MONITORING_TOKEN_SHA256`, para que el agente principal prepare el despliegue. No rotar silenciosamente una credencial existente; validar coherencia antes de reutilizarla. Admin de Grafana y secret_key aleatorios también van en archivos privados leídos mediante file provider.
4. Prometheus escuchará solamente `127.0.0.1:9090`, retención 30 días y límite TSDB 512 MB, sin admin/lifecycle API. Scrape cada 60 segundos, timeout 15 segundos, HTTPS con validación CA/hostname, sin redirects, endpoint exacto `/actuator/prometheus`, Bearer `credentials_file`, label `service_name=grownupsvet-backend`. El origen configurable debe ser una URL HTTPS raíz `*.run.app` sin credenciales, query, fragment o puerto alterno. Se documentará que el scrape puede mantener actividad de Cloud Run y consumir sus cuotas existentes; no se crean recursos ni facturación nueva.
5. Grafana escuchará solamente `127.0.0.1:3000`, SQLite privada, sin telemetría/update checks, usuarios/signup deshabilitados. Permitir Viewer anónimo únicamente en loopback para abrir el panel sin compartir credenciales. Admin aleatorio queda privado; no activar auth de pago. Provisionar datasource Prometheus fija `grownupsvet-local-prometheus`, apuntando a loopback. Copiar el dashboard existente a un archivo generado privado, sustituir solo datasource/selector y marcarlo read-only; preservar el JSON fuente original.
6. Antes de arrancar comprobar ocupación de ambos puertos y no detener procesos existentes. Lanzar ocultos con rutas/argumentos públicos y entorno reducido. Persistir PID, ruta exacta del ejecutable y hora UTC de inicio. Una segunda ejecución debe reconocer sus procesos; rechazar discrepancias. Parar únicamente los procesos que coincidan en esas tres propiedades y en el ejecutable esperado dentro del árbol privado. No matar por nombre/puerto ni usar autostart.
7. Validar config con promtool, JSON/provisioning y versiones. Verificar sockets loopback, readiness de Prometheus, health/datasource/dashboard de Grafana, rol Viewer/read-only y query `up`. Antes de desplegar `monitoring` se espera `up=0` (401/404) y se reportará como pendiente remoto, sin presentarlo como scrape de métricas real. El agente principal autoriza/despliega el perfil y hash después; solo entonces se espera `up=1` y se comprueban series HTTP/histogramas con tráfico real.
8. Probar parada/arranque y guardas con entradas sintéticas relevantes: URL/ruta incorrecta, token existente corrupto, puerto ocupado, PID ajeno/discrepante y hashes alterados. No Maven, Java/backend YAML, commit/push ni despliegue. Informar procesos/enlace local, hashes, pruebas y límites.
